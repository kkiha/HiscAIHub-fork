# AI 공유 허브 고도화 기획서

- 작성일: 2026-08-13
- 문서 목적: 고도화 방향과 활용 지표 체계에 대한 공통 인식 확보

---

## 1. 배경 및 목적

### 배경

- 생성형 AI 활용이 개인 역량에 의존하여, 구성원 간 활용 격차가 발생하고 있다.
- 우수한 활용 사례가 개인 메모·메신저에 흩어져 조직 차원의 재사용이 어렵다.
- 현재 사이트는 PoC 단계로, 콘텐츠 이용 현황이 기록되지 않는다.
- 부서별·업무별 AI 활용 현황을 확인할 수 있는 수단이 없다.

### 고도화 방향

> **기능 추가가 아닌, 활동이 기록되는 구조로 전환**

### 확인하고자 하는 3가지 질문

> `[다이어그램 ① 컨셉도]`

| # | 질문 | 관점 |
| - | --- | --- |
| 1 | **얼마나 쓰이는가** | 활성화 |
| 2 | **어떤 업무에 쓰이는가** | 업무유형 |
| 3 | **어디까지 퍼지는가** | 부서 확산 |

- 세 질문에 대한 답을 수치와 시각화로 제공하는 것이 목표다.
- 모든 지표 설계는 위 질문 중 하나에 대응하도록 구성한다.

## 3. 활용의 정의

- 지표 나열에 앞서 **무엇을 활용으로 볼 것인가**를 먼저 정의한다.
- 정의가 명확하지 않으면 동일한 수치에 대해 해석이 달라질 수 있다.

### 3-1. 측정 대상 행동

> `[다이어그램 ⑤ 사용자 행동 플로우]`

| 행동 | 기준 | 측정 여부 |
| --- | --- | --- |
| 방문 | 로그인 · 접속 | 대상 아님 |
| 조회 | 상세 페이지 확인 | 대상 아님 |
| **가져가기** | Claude로 실행 | **측정** |
| **등록** | 신규 에이전트 등록 | **측정** |

**가져가기·등록만 측정하는 이유**

- 방문·조회는 콘텐츠에 대한 관심 표현으로, 업무 적용 여부와 직접 연결되지 않음
- 측정 범위를 좁히는 대신 수집된 수치의 신뢰도를 확보
- 소비(가져가기)와 기여(등록) 양측을 함께 측정

**좋아요 제외 사유**

- 콘텐츠에 대한 반응 지표로, 실제 활용 여부와 무관
- 활용 측정은 가져가기 수로 충분
- 기능 자체를 삭제하고, 종합점수 가중치도 실행·등록 중심으로 재조정

### 3-2. 활성 사용자 정의

> **활성 사용자 = 선택한 기간 내 1회 이상 가져간 사용자**

- 화면의 기간 필터(7 / 30 / 90일)와 연동
- 대외 보고 시 **대표값은 30일 기준** 적용
- 사내 도구 특성상 7일 기준은 실제 활용 대비 낮게 산출될 수 있음
- 표기 시 기간 병기 (예: `활성 사용자 340명 (최근 30일)`)

**정의의 핵심**

- 콘텐츠 등록자뿐 아니라 **가져다 쓰는 사용자까지 포함**
- 소비 측 사용자를 포함해야 실제 확산 정도를 파악 가능

### 3-3. 부서 비교 원칙

- 부서 규모 차이로 인해 절대 건수만으로는 비교가 어렵다.

| 원칙 | 내용 |
| --- | --- |
| 절대값 + 비율 병행 | 가져가기 수와 인원 대비 비율을 함께 표시 |
| 소규모 부서 처리 | 10명 미만 부서는 개별 표시 제외 |
| 집계 단위 | 부서 단위 집계, 개인 실명 랭킹 비공개 |
| 목적 | 순위 비교가 아닌 활용 현황 파악 |

**인원 대비 비율 산출**

- 분모(부서별 인원수)는 초기 관리자 수동 입력
- 회사 계정 SSO 전환 시 조직 정보 연동을 통한 자동화 검토

## 4. 대시보드 구성안

> `[대시보드 목업]`

### 4-1. 화면 구조

```
현황 → 추이 → 업무유형 → 부서 확산 → 인기 콘텐츠
```

- 핵심 수치 → 시간에 따른 변화 → 세부 분석 순으로 구성
- 벤치마킹 사례(Glean Agents Insights)의 화면 구성 순서 참고

### 4-2. 블록별 표시 항목

| 블록 | 표시 항목 | 대응 질문 |
| --- | --- | --- |
| **현황** | 전체 등록 에이전트 수 / 활성 사용자 수 / 참여 부서 수 / 전체 가져가기 수 (각 증감률 병기) | 얼마나 |
| **추이** | 월별 등록 수 · 가져가기 수 · 활성 사용자 수 | 얼마나 |
| **업무유형** | 카테고리별 등록 분포 / 카테고리별 가져가기 분포 | 어떤 업무에 |
| **부서 확산** | 부서별 등록·가져가기 현황 (절대값 + 인원 대비 비율) | 어디까지 |
| **인기 콘텐츠** | 가져가기 상위 에이전트 / 타 부서에서 많이 가져간 에이전트 | 어디까지 |

### 4-3. 공통 필터

- 기간: 7 / 30 / 90일
- 부서: 전체 / 특정 부서

### 4-4. 부서별 활용현황 페이지

- 대시보드와 별도로 부서 단위 상세 페이지 제공

| 표시 항목 | 성격 |
| --- | --- |
| 부서별 등록 에이전트 수 | 기여 |
| 부서별 가져가기 수 | 활용 |
| 부서 내 인기 에이전트 | 활용 |
| **타 부서에서 많이 가져간 에이전트** | **확산** |
| **해당 부서 콘텐츠를 활용한 타 부서 수** | **확산** |

**확산 지표의 의미**

- `다른 부서가 우리 부서의 에이전트를 얼마나 가져갔는가`가 대표 확산 지표
- 부서 관점에서 성과로 인식 가능
- 등록 동기 부여 요소로도 활용

### 4-5. [별도 탭] 팀별 AI 구독 현황

- 조직 역량개발비 지원 내역 기준, 부서별 AI 도구 구독 계정 구성 및 비용
- **플랫폼 자동 수집이 아닌 외부 데이터**
- 월 1회 수동 갱신, 화면에 기준월 표기
- 자동 수집 지표와의 혼동 방지를 위해 별도 탭으로 분리
- 활용 지표와 교차 확인하는 보조 자료로 활용 (구독 대비 활용이 낮은 부서 식별 등)

## 5. 업무 카테고리

- `어떤 업무에 쓰이는가`에 대한 집계 기준으로 사용
- 에이전트 등록 시 **필수 선택** 항목으로 지정

| 카테고리 | 주요 내용 |
| --- | --- |
| **작성·요약** | 문서 작성, 보고서 작성, 내용 요약 |
| **조사·리서치** | 정보 검색, 자료 조사, 시장·산업 리서치 |
| **분석** | 데이터 분석, 비교·분류, 결과 해석 |
| **번역·검토** | 번역, 문장 교정, 내용 검토 |
| **기획·아이디어** | 아이디어 발굴, 기획안 작성, 브레인스토밍 |
| **자동화·개발** | 코드 작성, 반복업무 자동화, Workflow |

**운영 원칙**

- 카테고리는 **작업 유형** 기준으로 구성
- 업무 도메인(고객응대 · 컴플라이언스 · 영업 등)은 필요 시 2차 태그로 분리
- 부서 × 카테고리 데이터 축적 시 Heatmap으로 확장 가능

## 7. 이번 범위 밖 — 추후 검토

- 아래 항목은 방향성에는 동의하나, 이번 범위에서는 제외한다.

| 항목 | 제외 사유 | 도입 조건 |
| --- | --- | --- |
| **가져가기에 복사 포함** | 실행이 복사를 포함하는 상위 행동. 별도 집계 시 중복 소지 | 실행 지표 안정화 후 |
| **Git 연동 등록** | 사이트 외부 실행분이 활용 현황에 반영되지 않음 | 실행 현황 파악 방식 정리 후 |
| **조회 지표** | 관심과 활용의 구분을 위해 제외 | 필요성 판단 시 |
| **시간 절감 지표** | 주관적 추정 의존으로 신뢰도 확보 어려움 | 객관식 수집 데이터 축적 후 |
| **부서 × 업무유형 Heatmap** | 데이터량 부족 | 운영 데이터 확보 후 |
| **개인 단위 랭킹 공개** | 순위 비교가 아닌 현황 파악이 목적 | 운영 방향 재검토 시 |

**Git 연동 등록 관련 보충**

- 등록 편의성 측면에서 유효한 방향
- 현재 활용 측정 기준은 "사이트에서 Claude로 실행"
- Git 기반 에이전트는 각자 환경에서 실행되어 등록 수만 집계되고 활용 수는 미집계
- 실행 현황 파악 방식 정리 후 도입 검토가 적절

**시간 절감 지표 관련 보충**

- 등록 시 구간형 객관식 수집 방식 검토 가치 있음
  - 예: 1회 실행당 10분 미만 / 10~30분 / 30분~1시간 / 1시간 이상
- 초기 대시보드 핵심 지표에는 미노출
- 데이터 축적 후 신뢰도 확인하여 반영 여부 결정
