# AI 공유 허브 (Hisc AI Hub)

한화 임직원이 업무에 유용한 **AI 프롬프트와 에이전트**를 찾고, 공유하고, 재사용할 수 있도록 기획한 사내 플랫폼입니다.

현재 버전은 실제 운영 시스템이 아니라 **PoC(개념 검증용 시제품)**입니다. 서버나 데이터베이스를 구축하기 전에, 임직원이 어떤 화면을 보고 어떤 흐름으로 서비스를 이용할지 검토하는 것이 목적입니다.

## 현재 단계의 목표

이 PoC를 통해 다음 사항을 확인할 수 있습니다.

- 임직원이 필요한 프롬프트와 에이전트를 쉽게 찾을 수 있는지
- 검색, 상세보기, 좋아요, 저장, 댓글 등의 이용 흐름이 자연스러운지
- 프롬프트와 에이전트를 등록하고 관리하는 과정이 이해하기 쉬운지
- 부서별 활용 현황과 인기 콘텐츠를 관리자 화면에서 어떻게 보여줄지
- 향후 실제 시스템을 구축할 때 필요한 기능과 정책이 무엇인지

현재 화면에 표시되는 인증, AI 생성 결과, 통계 등은 시연용입니다. 실제 성능이나 운영 수치를 검증하는 단계는 아닙니다.

## 설치 없이 데모 실행하기

기획용 데모는 별도 프로그램 설치 없이 Chrome에서 바로 열 수 있습니다.

1. Windows 파일 탐색기에서 이 저장소의 `safe-demo` 폴더를 엽니다.
2. `login.html`을 마우스 오른쪽 버튼으로 누릅니다.
3. **연결 프로그램 → Google Chrome**을 선택합니다.
4. 화면에서 `회사 계정으로 로그인` 버튼을 누릅니다.

주소창이 `file://`로 시작하면 정상입니다. 다음 프로그램이나 서비스는 필요하지 않습니다.

- Node.js 또는 npm 설치
- 별도 웹 서버
- Docker
- PostgreSQL 또는 Prisma
- 외부 API
- 인터넷 연결

### 화면별 파일

| 파일 | 용도 |
| --- | --- |
| `safe-demo/login.html` | 임직원 로그인 흐름의 시작 화면 |
| `safe-demo/index.html` | 프롬프트·에이전트를 이용하는 사용자 화면 |
| `safe-demo/admin.html` | 운영 현황과 관리 기능을 확인하는 관리자 화면 |

관리자 화면은 `admin.html`을 Chrome으로 직접 열면 됩니다. 관리자 화면의 `서비스로 돌아가기`를 누르면 사용자 화면으로 이동합니다.

## 권장 시연 순서

전체 흐름은 약 5분 안에 확인할 수 있습니다.

1. 로그인 화면에서 임직원 전용 서비스의 진입 방식을 확인합니다.
2. 사용자 화면에서 프롬프트와 에이전트 모드를 전환합니다.
3. 전체, 인기, 저장, 내가 만든 것 메뉴와 검색을 사용합니다.
4. 콘텐츠 상세 화면에서 좋아요, 저장, 댓글, 복사를 확인합니다.
5. 프롬프트 또는 에이전트의 등록, 수정, 삭제 과정을 확인합니다.
6. AI가 프롬프트나 에이전트를 생성해 주는 화면 흐름을 확인합니다.
7. 에이전트 화면에서 파일명 선택과 시연용 실행 결과를 확인합니다.
8. 관리자 화면에서 Dashboard, 콘텐츠, 신고, 사용자, 사용량, 감사 로그, 설정 메뉴를 확인합니다.

## 실제로 동작하는 범위와 시연용 범위

화면 조작은 가능하지만, 데이터는 서버가 아닌 현재 브라우저 메모리에서만 변경됩니다.

| 기능 | 데모에서의 동작 | 실제 시스템 연동 여부 |
| --- | --- | --- |
| 화면 탐색과 검색 | 화면에서 바로 동작 | 서버 연동 없음 |
| 좋아요, 저장, 댓글 | 화면의 숫자와 상태가 변경됨 | 브라우저 메모리에서만 처리 |
| 콘텐츠 등록, 수정, 삭제 | 목록과 상세 화면에 반영됨 | 브라우저 메모리에서만 처리 |
| 프롬프트·지침 복사 | 브라우저 권한이 허용되면 클립보드에 복사 | 외부 전송 없음 |
| 임직원 로그인 | 버튼을 누르면 사용자 화면으로 이동 | 실제 Azure AD 인증은 수행하지 않음 |
| AI 자동 생성 | 생성 과정과 예시 결과를 표시 | 실제 LLM/API 호출 없음 |
| Claude 실행 | 안내 메시지만 표시 | Claude 앱이나 웹사이트를 열지 않음 |
| 파일 선택 | 선택한 파일명만 표시 | 파일 내용을 읽거나 전송하지 않음 |
| 에이전트 실행 | 진행 단계와 예시 결과를 표시 | 실제 파일 분석 없음 |
| 공유 | 안내 메시지만 표시 | 실제 공유 링크를 만들거나 전송하지 않음 |
| 관리자 Dashboard | 시연용 통계와 관리 동작을 표시 | 실제 사내 데이터와 연결되지 않음 |
| CSV 내보내기 | 완료 안내 메시지만 표시 | 실제 파일은 생성하지 않음 |

페이지를 새로고침하면 좋아요, 댓글, 등록 내용 등은 초기 상태로 돌아갑니다. 이는 데이터를 저장하지 않는 현재 PoC의 정상 동작입니다.

## 보안 및 데이터 처리 원칙

`safe-demo`는 회사 인터넷망용 가상 PC에서 외부 통신 없이 시연할 수 있도록 구성했습니다.

- 외부 API를 호출하지 않습니다.
- Claude 앱이나 외부 웹사이트를 열지 않습니다.
- CDN, 외부 JavaScript, 외부 폰트를 사용하지 않습니다.
- 로그인 ID나 비밀번호를 입력받거나 저장하지 않습니다.
- 사용자가 선택한 파일의 이름만 표시하며 파일 내용은 읽지 않습니다.
- 파일이나 입력 내용을 외부로 전송하지 않습니다.
- 브라우저의 영구 저장 공간에 이용 데이터를 남기지 않습니다.
- 각 HTML 파일에 외부 연결을 차단하는 보안 정책(CSP)을 적용했습니다.

따라서 이 데모에 실제 고객정보, 계좌정보, 사내 비공개 자료를 입력하거나 업로드할 필요가 없습니다. 화면 검토에는 반드시 예시 문구와 테스트용 파일명을 사용해 주세요.

## 이번 PoC로 판단할 수 없는 사항

다음 항목은 실제 시스템 구축 단계에서 별도로 검증해야 합니다.

- Azure AD SSO의 실제 인증과 권한 관리
- 동시 사용자 수에 따른 성능과 안정성
- 실제 데이터 저장, 백업, 복구
- LLM 응답 품질과 처리 시간
- 파일 분석 정확도와 허용 가능한 파일 형식
- 실제 사용량, 비용, 부서별 통계
- 개인정보 및 사내 정보에 대한 운영 보안 심사

## 저장소 구조

```text
HiscAIHub-fork/
├─ safe-demo/                  # 설치 없이 실행하는 기획용 정적 PoC
│  ├─ login.html               # Azure AD SSO 화면 Mock
│  ├─ index.html               # 프롬프트·에이전트 사용자 화면
│  └─ admin.html               # 관리자 Dashboard 화면
│
├─ design-reference/           # 디자인 기준 원본 HTML
├─ src/                        # 기존 Next.js 애플리케이션
├─ prisma/                     # 기존 DB 스키마·마이그레이션·시드
├─ public/                     # 기존 정적 리소스
├─ admin-dashboard-mockups/    # 관리자 화면 검토 자료
├─ AGENTS.md                   # 프로젝트 작업 규칙
└─ CLAUDE.md                   # 프로젝트 작업 규칙
```

`safe-demo`는 기존 구현을 삭제하거나 대체하지 않습니다. 기존 Next.js와 Prisma 기반 코드는 그대로 보존하고, 기획 검토용 정적 화면을 별도 영역으로 추가했습니다.

## 개발자 참고 사항

아래 내용은 기존 운영형 구현을 다루는 개발자를 위한 안내입니다. 화면 시연만 필요하다면 이 절의 작업을 수행할 필요가 없습니다.

기존 애플리케이션은 Next.js App Router + Prisma + PostgreSQL 기반이며, AI 자동 생성 기능은 백엔드에서 Anthropic API를 호출하도록 구성되어 있습니다.

### 주요 환경 변수

- `DATABASE_URL` — PostgreSQL 접속 정보
- `AUTH_SECRET`, `ADMIN_SECRET` — 세션 서명 키
- `ALLOWED_EMAIL_DOMAIN` — 허용할 임직원 이메일 도메인
- `EMPLOYEE_DEV_PASSWORD` — 기존 코드가 참조하는 개발용 임시 값으로, 운영 사용 금지
- `ADMIN_ID`, `ADMIN_PW` — 임직원 인증과 분리된 임시 관리자 인증
- `ANTHROPIC_API_KEY` — 백엔드 AI 생성 기능에서만 사용하는 키

비밀정보와 API 키는 반드시 `.env`에 두며 프런트엔드 코드에 넣지 않습니다. 실제 임직원 인증은 `@hanwha.com` Azure AD SSO만 사용하는 것이 원칙이며 자체 비밀번호를 저장하지 않습니다.

### 주요 개발 명령

```bash
npm run dev
npm run build
npx prisma migrate dev
npm run db:seed
```

회사 보안정책이나 인증서 검증을 우회해 의존성을 설치하거나 외부 서비스에 연결하지 마세요. 단순 화면 시연이 목적이라면 위 명령을 실행하지 말고 `safe-demo/login.html`을 사용하면 됩니다.

## 프로젝트 기본 원칙

- 디자인 기준은 `design-reference/`의 세 HTML입니다.
- 포인트 색상은 오렌지 `#D96A28`이며 미니멀한 표현을 유지합니다.
- LLM과 외부 API는 운영형 구현에서도 반드시 백엔드를 거칩니다.
- 임직원 인증과 관리자 인증은 분리합니다.
- 저장(Save)은 비공개이며 집계·알림 대상이 아닙니다.
- 좋아요는 공개 반응입니다.
- DB 접속 정보, 비밀정보, API 키는 코드에 하드코딩하지 않습니다.
